# Модель

> Эта версия (ветка `feature/segmentation`) заменяет бинарный классификатор
> (EfficientNet-B3, BreakHis) на попиксельную семантическую сегментацию тканей,
> обученную на **BCSS**. Метрики и датасет старой модели (AUC-ROC 0.9953,
> accuracy 97%, BreakHis) относятся только к бинарному классификатору на
> `master` и **не переносятся** на эту модель — задачи разные (классификация
> одного числа vs. поклассовая карта пикселей), сравнивать напрямую нельзя.

## Обзор

| | |
|---|---|
| Архитектура | DeepLabV3+ (`segmentation_models_pytorch`), энкодер ResNet-18 |
| Классы | 16 классов тканей BCSS + служебный класс `ignore` (см. ниже) |
| Вход | RGB 256×256, нормализация по статистикам ImageNet |
| Обучающий датасет | BCSS (Breast Cancer Semantic Segmentation), частичная выборка |
| mIoU | **не подтверждён** — см. «Честность в отношении метрик» ниже |
| Устройство инференса | CPU (GPU не требуется) |
| Explainability | сама маска сегментации — поклассовая карта пикселей, отдельного explainability-слоя не требуется (GradCAM++ был нужен для объяснения решения одного скалярного классификатора; сегментация уже даёт пространственную интерпретацию) |

Веса (`models/segmentation.pth`) распространяются отдельно от кода — обучаются на стороне пользователя (см. «Как обучить» ниже) и монтируются в `models/` (каталог вне git), путь задаётся `segmentation_model.weights_path` в `config/config.yaml`.

## Таксономия классов (`config/bcss_classes.yaml`)

BCSS размечен по официальной таксономии из `PathologyDataScience/BCSS` — 22 сырых кода (`0 = outside_roi` + 21 класс ткани). Для этого проекта 21 сырой класс сгруппирован в 16 рабочих классов — объединены только действительно редкие/близкородственные (например, `angioinvasion → tumor`, `plasma_cells → other_immune_infiltrate`); клинически различимые категории оставлены раздельно (в частности, `tumor` отдельно от `dcis` — это соответствует границе применимости старой модели «инвазивная карцинома vs DCIS»). `outside_roi` (сырой код 0) — игнорируемый класс: исключён из loss и из mIoU, как рекомендует сама документация датасета.

## Честность в отношении метрик

**На этой CPU-машине разработки полноценное обучение не проводилось** — она годится для инференса, но не для обучения на полном датасете (8 CPU, без GPU). Обучение прогонялось на Google Colab (T4 GPU, `notebooks/train_segmentation_colab.ipynb`) на частичной выборке BCSS. Точный mIoU этого прогона не был надёжно зафиксирован (см. `segmentation_model.metrics_summary` в `config/config.yaml` — placeholder, а не число). Ручная проверка на реальном тканевом кропе показала среднюю уверенность модели (`mean_confidence`) на уровне ≈0.09 — едва выше случайного baseline'а 1/16 ≈ 0.0625 для 16 классов, то есть **текущий чекпоинт, скорее всего, недообучен** и годится для демонстрации сквозного пайплайна (данные → маска → площади → вердикт → PDF), но не для содержательной точности классификации тканей.

Полноценное обучение (полный датасет BCSS, больше эпох, подбор гиперпараметров) должно проводиться на стороне пользователя, где есть GPU — код обучения (`src/training/`, notebook) написан переносимым для этого. После такого обучения `segmentation_model.metrics_summary` и эта таблица должны быть обновлены реальными mIoU/per-class IoU, посчитанными `src/training/metrics.py::ConfusionMatrix`.

Дисклеймер СППР («Система поддержки принятия решений. Окончательное заключение формулирует врач-патологоанатом», `config/config.yaml` → `app.disclaimer`) обязателен везде, где показывается результат модели — в API-ответах, на фронтенде и в PDF-отчёте — независимо от качества текущего чекпоинта.

## Область применения

- Многоклассовая сегментация тканей молочной железы (16 классов BCSS выше) — не бинарная классификация всего препарата.
- Только H&E-окраска.
- Только рак молочной железы.
- Вердикт («злокачественная»/«доброкачественная») выводится из площади классов `tumor`+`dcis` (см. `src/inference/verdict.py`) — это упрощение поверх сегментационной карты, не самостоятельный клинический вывод по стадированию/типированию.

## Как обучить (на стороне пользователя, с GPU)

Обучающий код входит в этот репозиторий (`src/training/`), в отличие от старой бинарной модели:

1. **Датасет.** Скачать все 151 регион BCSS через `python -m src.training.prepare_bcss download-official --out data/bcss` — RGB-регионы через Girder REST API официального демо-сервера HistomicsTK, маски по прямым Figshare-ссылкам из `meta/roiBounds.csv` (`PathologyDataScience/BCSS`'а), без дневной квоты Google Drive, которая раньше обрывала докачку на середине. Резюмируемо (уже скачанные пары пропускаются). Старый путь через `gdown`/Google Drive (`prepare_bcss.py download`) остаётся как fallback. `notebooks/train_segmentation_colab.ipynb` уже использует `download-official` и монтирует Google Drive для устойчивости к обрыву сеанса. Скрипт ремаппит сырые GT-маски в 16 классов по `config/bcss_classes.yaml`.
2. **Обучение.** `python -m src.training.train --data-dir data/bcss --out models/segmentation.pth --encoder resnet18 --stain-normalize` (см. `--help` для полного списка опций). Loss — взвешенный CE + Dice (`src/training/losses.py::WeightedCeDiceLoss`, веса классов — обратная частота по обучающей выборке, капается на `max_imbalance_ratio` (по умолчанию 50×), чтобы редчайший класс не дестабилизировал обучение — компенсирует сильный дисбаланс BCSS, `tumor`/`stroma` на порядки чаще `nerve`/`blood_vessel`, но без экстремальных весов). Метрики — per-class IoU + mIoU по confusion matrix (`src/training/metrics.py`), считаются на валидации каждую эпоху; отдельно логируется mIoU по клинически значимому подмножеству классов (`tumor`, `dcis`, `stroma`, `lymphocytic_infiltrate`, `necrosis_or_debris`, `normal_acinus_or_duct`) — на небольшом датасете он показательнее среднего по всем 16, часть которых (`nerve`, `undetermined`, ...) почти не встречается. Обучение останавливается по плато val mIoU (`--patience`/`--min-epochs`), не по жёстко заданному числу эпох. `--resume-path`/`--history-jsonl` пишут полное состояние (веса+оптимизатор+эпоха) и лог по эпохам на диск после каждой эпохи — при обрыве сессии (актуально для бесплатного Colab) повторный запуск той же команды продолжает с последней сохранённой эпохи, а не с нуля.
3. **Препроцессинг обучения** должен совпадать с инференсом: resize 256×256, нормализация ImageNet-статистиками (`segmentation_model.normalize_mean/std` в конфиге). При изменении препроцессинга — обновлять эти значения в конфиге, а не в коде.
4. **Замена весов.** Обученный `state_dict` сохранить как `models/segmentation.pth` (или путь из `segmentation_model.weights_path`), обычный `torch.save(model.state_dict(), ...)`, совместимый с `src/inference/segmenter.py::load_segmentation_model`.
5. **Смена энкодера/архитектуры.** Обновить `segmentation_model.encoder_name` в конфиге; `segmentation-models-pytorch` поддерживает смену энкодера без изменения кода (`build_model()` в `src/training/train.py` и `src/inference/segmenter.py` читают его из конфига).

## Ограничения инференса

- CPU-инференс: один патч (256×256) — доли секунды; полный WSI-препарат — бюджет `segmentation_wsi.max_processing_minutes` (по умолчанию 15 минут). **Реально измеренное время** на демонстрационном тестовом файле `CMU-1-Small-Region.svs` (2220×2967 px, небольшой фрагмент, не полноразмерный гигапиксельный препарат) — **≈30 секунд** сквозь весь HTTP-пайплайн (`/analyze/wsi` → фоновая задача → результат), в реальном Docker-стеке. Время на полноразмерном гигапиксельном WSI (десятки тысяч × десятки тысяч px) на этой машине не измерялось — экстраполяция по количеству тайлов предполагает, что бюджет в 15 минут может быть тесным на CPU без дополнительной оптимизации (батчинг уже используется, `segmentation_wsi.batch_size`); при необходимости — профилировать на реальном полноразмерном препарате и при необходимости упрощать декодер (см. ALGORITHMS.md §4).
- Модель загружается один раз на процесс (`src/api/ml_runtime.py::get_segmenter`) — конкурентный инференс внутри одного процесса не распараллеливается; масштабирование — через несколько worker-процессов.
