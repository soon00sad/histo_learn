# Архитектура

## Модули и слои

```
                      ┌─────────────┐
                      │  frontend/  │  React + TS + Vite
                      │  (5 экранов)│
                      └──────┬──────┘
                             │ REST/JSON + multipart, JWT в заголовке
                      ┌──────▼──────┐
                      │  src/api/   │  FastAPI: роутеры, аутентификация,
                      │             │  SQLAlchemy-модели (SQLite)
                      └──────┬──────┘
           ┌─────────────────┼─────────────────┐
    ┌──────▼──────┐   ┌──────▼───────┐   ┌──────▼──────┐
    │ src/wsi/    │   │ src/inference│   │ src/report/ │
    │ reader,     │──▶│ model,       │──▶│ pdf_report  │
    │ tiler       │   │ classifier,  │   │ (ReportLab) │
    └─────────────┘   │ wsi_aggreg.  │   └─────────────┘
    ┌─────────────┐   └──────┬───────┘
    │preprocessing│          │
    │tissue_filter│◀─────────┤
    │stain_norm.  │          │
    └─────────────┘   ┌──────▼──────┐
                       │  src/xai/   │  GradCAM++, top-K зоны
                       └─────────────┘
```

Каждый модуль — независимый пакет с чёткими входами/выходами (dataclasses), без взаимных циклических зависимостей. `src/utils/config.py` — единственный источник конфигурации (Pydantic-модели, загружаемые из `config/config.yaml`), `src/utils/logging.py` — единственная точка настройки логирования.

## Поток данных

### Анализ одного патча (синхронный, секунды)

```
Загрузка PNG/JPEG
  → PatchClassifier.classify()        (src/inference/classifier.py)
  → GradCamExplainer.explain()         (src/xai/gradcam.py)
  → top_k_regions()                    (src/xai/regions.py)
  → сохранение Case в БД + файлов на диск
  → JSON-ответ клиенту
```

### Анализ WSI (асинхронный job, до ~15 минут на CPU)

```
POST /analyze/wsi (файл сохраняется синхронно)
  → создаётся Job(status=queued), FastAPI BackgroundTasks
  → analyze_wsi() (src/inference/wsi_aggregator.py):
      1. WsiReader читает пирамиду (src/wsi/reader.py)
      2. plan_tiles(): тепловая карта тканей по миниатюре → координаты тайлов
         (src/wsi/tiler.py, src/preprocessing/tissue_filter.py)
      3. для каждого тайла: Macenko-нормализация → батч-инференс
      4. агрегация вероятностей тайлов → вердикт препарата
      5. построение тепловой карты по всему препарату
  → прогресс пишется в Job на каждом этапе (поллинг с фронтенда)
  → создаётся Case, Job.status=done, Job.case_id=<id>
```

Frontend поллит `GET /api/v1/jobs/{id}` каждые 1.5 с (экран «Обработка») и переходит к результатам, как только `status=done`.

## Ключевые архитектурные решения

- **SQLite вместо отдельной СУБД.** On-premise развёртывание — один инстанс на медучреждение, без внешнего клиента к БД. Файл БД лежит в volume `data/`. Замена на Postgres при необходимости масштабирования не требует правки вызывающего кода — весь доступ идёт через `sqlalchemy.orm.Session`, полученную из `src/api/db.py`.
- **BackgroundTasks вместо очереди задач (Celery/RQ).** Для одного инстанса и последовательной обработки WSI-препаратов очередь избыточна. Если потребуется параллельная обработка нескольких WSI одновременно — это осознанная граница текущей архитектуры, а не забытая деталь.
- **Единственный процесс с одним воркером ML-инференса.** `src/api/ml_runtime.py` держит `PatchClassifier`/`GradCamExplainer` как процесс-синглтон: `pytorch_grad_cam` регистрирует хуки на модели при создании и не отсоединяет их автоматически, поэтому создавать новый `GradCamExplainer` на каждый запрос — утечка хуков. Масштabирование на несколько worker-процессов (`uvicorn --workers N`) просто означает, что каждый процесс независимо платит одну и ту же цену загрузки модели — конкурентность внутри одного процесса не предполагается для MVP.
- **JWT + один/несколько пользователей вместо полноценной системы ролей.** Клиника — один периметр; разграничение врач/администратор вне рамок v1.0.
- **Тепловая карта WSI — мозаика вероятностей тайлов, не пер-тайловый GradCAM++.** Прогон GradCAM++ на тысячах тайлов на CPU не уложился бы в целевые 15 минут. Для полного препарата используется вероятность злокачественности каждого тайла как значение тепловой карты (см. docs/ALGORITHMS.md, «Агрегация»); GradCAM++ применяется точечно в режиме «Живой анализ» на одном патче.
- **OpenSlide — мягкая (soft) зависимость.** На Windows-машинах без нативной библиотеки OpenSlide сервис всё равно поднимается и работает в режиме анализа патчей; WSI-эндпоинт возвращает понятную ошибку вместо падения процесса (`src/wsi/reader.py::OpenSlideUnavailableError`).

## Безопасность и приватность

- Все эндпоинты с данными пациентов (`/analyze/*`, `/cases/*`) требуют JWT.
- Изображения/тепловые карты/PDF отдаются через авторизованные эндпоинты (`FileResponse` за `Depends(current_user)`), а не через публичный `StaticFiles` — исключён прямой доступ к каталогу с данными пациентов.
- Пароли — bcrypt (passlib). JWT-секрет и пароль дефолтного пользователя — только через переменные окружения в реальном развёртывании (см. README).
