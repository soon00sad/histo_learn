# Архитектура

> Эта версия (`feature/segmentation`) заменяет бинарный классификатор
> сегментацией — ниже описан текущий (сегментационный) поток. `master`
> остаётся нетронутым рабочим fallback'ом со старой архитектурой
> (`PatchClassifier` + `GradCamExplainer` + `wsi_aggregator.py`), на случай
> если сегментационная модель не готова к демонстрации к дедлайну.

## Модули и слои

```
                      ┌─────────────┐
                      │  frontend/  │  React + TS + Vite
                      │  (5 экранов)│
                      └──────┬──────┘
                             │ REST/JSON + multipart, JWT в заголовке
                      ┌──────▼──────┐
                      │  src/api/   │  FastAPI: роутеры, аутентификация,
                      │             │  SQLAlchemy-модели (SQLite)
                      └──────┬──────┘
           ┌─────────────────┼─────────────────┐
    ┌──────▼──────┐   ┌──────▼───────┐   ┌──────▼──────┐
    │ src/wsi/    │   │ src/inference│   │ src/report/ │
    │ reader,     │──▶│ segmenter,   │──▶│ pdf_report  │
    │ tiler       │   │ wsi_segmenter│   │ (ReportLab) │
    └─────────────┘   │ verdict      │   └─────────────┘
    ┌─────────────┐   └──────┬───────┘
    │preprocessing│          │
    │tissue_filter│◀─────────┤
    │stain_norm.  │          │
    └─────────────┘   ┌──────▼──────┐
                       │src/training/│  датасет, loss, метрики,
                       │             │  цикл обучения (офлайн, не в API)
                       └─────────────┘
```

`src/xai/` (GradCAM++, top-K зоны) остаётся в дереве кода нетронутым — он всё ещё используется веткой `master`, но никуда не вызывается из сегментационного пути: маска сегментации уже является пространственным объяснением сама по себе (см. docs/ALGORITHMS.md §6), отдельный explainability-слой ей не нужен.

Каждый модуль — независимый пакет с чёткими входами/выходами (dataclasses), без взаимных циклических зависимостей. `src/utils/config.py` — единственный источник конфигурации (Pydantic-модели, загружаемые из `config/config.yaml`; секции `segmentation_model`/`segmentation_wsi`/`segmentation_verdict` — отдельно от старых `model`/`wsi`, чтобы не ломать `master`), `src/utils/logging.py` — единственная точка настройки логирования.

## Поток данных

### Анализ одного патча (синхронный, доли секунды)

```
Загрузка PNG/JPEG
  → PatchSegmenter.segment()          (src/inference/segmenter.py)
      resize/normalize → softmax по 16 классам → argmax-маска + доли площади
  → derive_verdict()                   (src/inference/verdict.py)
  → сохранение Case в БД + PNG-маски (индексированная, лossless) на диск
  → JSON-ответ клиенту
```

### Анализ WSI (асинхронный job, целевой бюджет ~15 минут на CPU)

```
POST /analyze/wsi (файл сохраняется синхронно)
  → создаётся Job(status=queued), FastAPI BackgroundTasks
  → analyze_wsi_segmentation() (src/inference/wsi_segmenter.py):
      1. WsiReader читает пирамиду (src/wsi/reader.py)
      2. plan_tiles(): маска тканей по миниатюре → координаты перекрывающихся
         тайлов (src/wsi/tiler.py, src/preprocessing/tissue_filter.py)
      3. для каждого тайла: Macenko-нормализация → батч-инференс → softmax
      4. накопление вероятностей в canvas препарата через окно Ханна
         (сшивка без швов на границах тайлов — см. ALGORITHMS.md §5)
      5. argmax canvas'а → маска препарата + доли площади по классам → вердикт
  → прогресс пишется в Job на каждом этапе: tiling → inference → stitching
    (поллинг с фронтенда)
  → создаётся Case (маска сохраняется как индексированный PNG), Job.status=done
```

Frontend поллит `GET /api/v1/jobs/{id}` каждые 1.5 с (экран «Обработка») и переходит к результатам, как только `status=done`.

## Ключевые архитектурные решения

- **SQLite вместо отдельной СУБД.** On-premise развёртывание — один инстанс на медучреждение, без внешнего клиента к БД. Файл БД лежит в volume `data/`. Замена на Postgres при необходимости масштабирования не требует правки вызывающего кода — весь доступ идёт через `sqlalchemy.orm.Session`, полученную из `src/api/db.py`.
- **BackgroundTasks вместо очереди задач (Celery/RQ).** Для одного инстанса и последовательной обработки WSI-препаратов очередь избыточна. Если потребуется параллельная обработка нескольких WSI одновременно — это осознанная граница текущей архитектуры, а не забытая деталь.
- **Единственный процесс с одним воркером ML-инференса.** `src/api/ml_runtime.py` держит сегментационную модель (`get_segmenter()`) как процесс-синглтон — загрузка весов один раз, не на каждый запрос. Масштабирование на несколько worker-процессов (`uvicorn --workers N`) означает, что каждый процесс независимо платит одну и ту же цену загрузки модели — конкурентность внутри одного процесса не предполагается для MVP.
- **JWT + один/несколько пользователей вместо полноценной системы ролей.** Клиника — один периметр; разграничение врач/администратор вне рамок v1.0.
- **Маска сегментации хранится как lossless индексированный PNG, не JPEG.** Байтовое значение пикселя — это class ID; JPEG-сжатие исказило бы точные индексы классов на границах, чего не было проблемой для старой тепловой карты (непрерывный скаляр, для которого лёгкая JPEG-потеря приемлема). Непокрытые пиксели (`UNCOVERED=255`) кодируются прозрачной палитровой записью (`tRNS`-чанк) — фронтенд накладывает маску полупрозрачным слоем поверх изображения ткани, и непокрытые области естественно показывают исходную ткань, а не фиктивный цвет класса.
- **Перекрывающиеся тайлы + блендинг окном Ханна вместо мозаики без нахлёста.** Бинарный путь (`master`) выдаёт один скаляр на тайл — сеточные швы там не создают визуальной проблемы. Посегментная сегментация предсказывает целую карту на тайл; без перекрытия и блендинга границы соседних тайлов давали бы видимые скачки класса. `segmentation_wsi.tile_stride < tile_size` (50% нахлёст) + Hann-взвешенное накопление устраняют это (см. ALGORITHMS.md §5).
- **OpenSlide — мягкая (soft) зависимость.** На Windows-машинах без нативной библиотеки OpenSlide сервис всё равно поднимается и работает в режиме анализа патчей; WSI-эндпоинт возвращает понятную ошибку вместо падения процесса (`src/wsi/reader.py::OpenSlideUnavailableError`).
- **Обучение (`src/training/`) — отдельный офлайн-модуль, не часть API-рантайма.** CLI (`python -m src.training.train`), никогда не импортируется из `src/api/`. Предназначен для запуска на машине с GPU (см. docs/MODEL.md) — на этой (CPU-only, ограниченная RAM) машине использовался только как smoke-тест пайплайна, не для реального обучения.

## Безопасность и приватность

- Все эндпоинты с данными пациентов (`/analyze/*`, `/cases/*`) требуют JWT.
- Изображения/тепловые карты/PDF отдаются через авторизованные эндпоинты (`FileResponse` за `Depends(current_user)`), а не через публичный `StaticFiles` — исключён прямой доступ к каталогу с данными пациентов.
- Пароли — bcrypt (passlib). JWT-секрет и пароль дефолтного пользователя — только через переменные окружения в реальном развёртывании (см. README).
